# 洛圣都手机：本地生活模拟设计

2026-11-07 用户提出：选择 Michael / Franklin / Trevor；随机来电聊天或派任务；在任务列表完成模拟任务；网页查看资金。本文是待实现方案，不代表当前固件已有这些能力。

## 已有画面的验证方式

preview.py 将同一份 phone.c、ui.c 和生成内容表链接桌面 LVGL，使用软件显示驱动输出 240×320 PNG。它模拟显示输出和部分状态转换，不模拟 ESP32、ADC 三键、I2S/codec、Flash 或整块 AiPassport。主机渲染、目标构建和真机验收分别报告。

## 产品行为

保留游戏手机桌面入口。首次启动在手机界面之前选择角色，之后通过单独的角色切换操作返回选择，不把角色选择硬塞进原版设置菜单。每个角色独立保存余额、任务、未读消息、关系与已触发事件；切换角色时暂停该角色正在进行的事件，避免跨角色错发短信或结算。

角色选择和模拟任务提交属于本设备的演示能力。原版素材、原版功能与本地改编流程在来源记录中分开，不能标成全部源自游戏。

## 第一条可验收流程

1. 角色处于空闲状态，调度器选一个满足条件的来电。
2. 来电显示已核对的发送者。拒接进入未接记录，稍后收到提示；接听播放该通话真实对应的游戏录音。
3. 通话结束后，任务出现在 Check List。用户可查看详情，选择接受/放弃；接受后才能在列表提交模拟完成。
4. 提交后只结算一次，增加虚拟余额，写入交易记录，并安排后续短信或回电。
5. Internet 内的离线演示页面显示本角色的余额与交易；不连接真实银行或真实账户。
6. 重启恢复该角色进度。重复提交、重复音频完成回调、角色切换不得重复发钱。

未找到正确通话录音的事件先不进入随机语音池。答录机只用于答录机场景；不能用答录机录音假装对方来电聊天。没有原版对应素材时，新写文字事件明确标为本地演示内容，不生成角色仿声冒充原声。

## 随机事件池

首轮建议 12 个事件模板，每位角色 4 个：一次委托、一次闲聊、一次关系/家庭消息、一次任务后的回应。模板可以使用多个真实原版片段，但只有素材链核对后才启用。

事件不是等概率抽取。根据当前角色、未完成任务、最近来电、上次事件、已解锁内容和冷却时间筛选，再做加权随机。任务链中的回应优先于无关闲聊。短时间内不重复同一事件；未接电话不无限重拨。

默认安静节奏为每 3–8 分钟一次机会，活跃演示为每 45–90 秒一次机会；这些时间是产品建议，不是游戏脚本提取值。可手动触发一个符合条件的事件以便拍摄展示。睡眠模式不来电，退出后也不集中补发。通话、拨号、角色切换和存档期间不插入新来电。

## 角色差异

三位角色分别建立联系人与素材白名单、独立账户和事件状态。事件方向可参考：Franklin 的工作和朋友，Michael 的家庭与旧关系，Trevor 的伙伴与突发状况。具体台词、联系人和情节必须回到原版资源核对，这里只定义产品方向。

角色的原版手机品牌和界面不同。当前可用界面是 Michael 的 iFruit；其他角色不能仅替换名字就宣称完成原版手机还原。可以先让三套进度在当前开发界面工作，再分别提取、接入其原版界面，并明确阶段状态。

## 任务与网页

Check List 承担轻量模拟任务：查看信息、确认联系、选择方案、提交完成。任务步骤服务于来电/短信反馈，不要求现实跑腿。原版任务列表界面和新增的提交操作需分别记录来源。

Internet 首轮只做少量可交互离线页面：账户/交易、精选商品、剧情新闻。消费可扣除虚拟资金并触发后续消息，交易和奖励均有独立事件 ID 防止重复处理。之后再评估股票、虚拟购车、物业收入；首轮不建设无关联的庞大网页库。

## 实现顺序与数据

先增加纯 C 的事件与角色状态模块，定义事件 ID、角色白名单、条件、权重、冷却、原版声音/文字引用、任务和奖励、后续事件。事件内容放 assets 下一个平铺 JSON；生成只读表进入 Flash，不给每个事件建文件夹。

第一阶段完成一条角色→来电→任务→完成→到账→短信的闭环，再加入角色独立保存与交易页面，最后扩大事件池。音频完成/挂断只负责推进相应事件，不直接修改任意任务或余额；存档使用版本与边界校验。

验证重点包括：拒接、通话中禁止插播、睡眠冷却、不重复奖励、余额非负与溢出、切换角色隔离、重启恢复、缺失音频回退。先主机验证，再 LVGL 实际渲染与固件构建，最后进行真机长时间随机运行。

## 2026-11-07 实现增补
